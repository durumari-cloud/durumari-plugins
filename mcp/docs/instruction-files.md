# 지침 파일과 세션 시작 주입

## 파일 구조

| 파일 | 읽는 호스트 | 두루마리가 쓰는 내용 |
|---|---|---|
| `AGENTS.md` | Codex, Cursor, Copilot, OpenCode (Claude Code·Gemini CLI는 가져오기로) | 관리 블록 전체: 두루마리 기본 규칙만(주입값이 로컬 문서·메모리보다 우선하고 차이를 알림, 주입이 없거나 연결이 끊기면 작업 전 알림, 관리 파일 편집 금지, 저장은 서버 영수증으로만 확정, 비밀값 비출력·비저장, Context 사용법, Policy 확인) |
| `CLAUDE.md` | Claude Code | 관리 블록 안에 `@AGENTS.md` 한 줄. 블록 밖에 이미 가져오기가 있으면 줄을 넣지 않음 |
| `GEMINI.md` | Gemini CLI | `CLAUDE.md`와 같음 |

- 관리 표시(`<!-- DURUMARI MANAGED BEGIN/END -->`) 사이만 바꾸고, 사용자의 다른 내용·다른 도구 설정은 그대로 둔다. 표시가 깨진 파일은 고치지 않고 연결 시 `invalid_managed_instructions`로 알린다.
- 연결(`context-connect`)은 선택한 호스트의 파일만 만든다. 다만 `AGENTS.md`는 가져오는 파일이 비어 있는 원본을 가리키지 않도록 항상 블록을 받는다. 새로 만든 파일은 `.durumari/context-binding.json`의 `created_files`에 남아 연결 제거 때 비면 지운다.
- 관리 블록에는 바뀌는 값(응답 언어, 팀 규칙 요약)을 넣지 않는다. 커밋된 파일이 사람·설정마다 바뀌지 않고, 한 팀의 규칙이 다른 팀 저장소에 들어가지 않게 하기 위해서다. 최신 값은 세션 시작 주입으로 전한다.
- 팀 규칙(예: 작업 claim·push 전 검사·병합 담당)은 바인딩 기본값에 넣지 않는다. 제품이 줄 것은 범용 장치(선행 명령 성공 기록 조건, 명령 거부, 세션 시작 실행)이고, 명령과 내용은 각 팀이 정한다(4단계).

## 기존 설치 변환(업데이트 계약 사용자 기기 계층)

0.4.11 이하는 `CLAUDE.md`·`GEMINI.md`에 블록 전체를 복사했다. 0.4.12 runtime은 세션 시작 훅에서 한 번 확인해, 이미 관리 블록이 있는 파일만 새 구조로 바꾸고 바꾼 파일 이름을 알린다. 관리 블록이 없는 파일은 만들지 않는다. 변환에 실패하면 다음 세션에서 다시 시도하고 훅은 막지 않는다.

## 세션 시작 훅 주입

| 항목 | 내용 |
|---|---|
| 연결 프로젝트 | `bound project=<ID>` |
| Policy 목록 | 언제·제목·ID@버전, 최대 30개 |
| 응답 언어 | `GET /api/v2/agent/connection`의 `language.response`(계정 선호 언어, 답·보고)와 `language.shared_documents`(구름 기본 언어, 공유 Context 문서). Policy 목록과 같은 1.5초 안에 읽는다. 필드가 없으면(0067 이전 서버) "사용자 최근 메시지 언어" |
| 압축 후 재주입 | Claude Code는 압축 뒤 `SessionStart`(`source: compact`)가 다시 오므로 같은 대화에서도 다시 주입한다. Codex는 압축 이벤트가 없어 시작·재개 때만 주입한다 |
| 연결 끊김 | 서버가 답하지 않거나 연결 확인이 실패하면 `두루마리 연결 끊김, 캐시 사용 (<시각> 기준)` 또는 `… 캐시 없음`을 표시하고, 마지막으로 받은 Policy 목록(캐시)과 "작업 전에 사용자에게 알릴 것"을 주입한다 |

캐시는 사용자 상태 폴더의 `hook-health/<profile>/session-snapshot.json`(권한 0600)에 Policy 제목·when·ID·버전과 응답 언어만 둔다. 문서 본문과 자격 증명은 넣지 않는다.
